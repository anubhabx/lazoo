## CLI entry points

```powershell
lazooctl system budget
lazooctl terminal --help
lazooctl memory --help
lazooctl memory-worker show
lazooctl provider config-preview --selection '<selected MCP JSON>'
lazooctl provider config-apply <operation-id> --expected-revision <revision>
lazooctl provider config-rollback <operation-id> --expected-revision <revision>
```

Memory retention/injection can be disabled independently. Changing retention does not delete existing evidence. Worker configuration is absent by default; enabling it is an explicit choice to send source excerpts through the selected native employee and its configured provider. Use a dedicated dormant employee: ordinary active sessions defer admission and are never repurposed or stopped for background summaries.

## Remaining core v1 acceptance boundaries

1. Complete the broader native lifecycle acceptance beyond the four passing short smoke tests: tools, permission behavior, cancellation, resume/recovery, and terminal attachment where supported. Grok is excluded; Claude's native subscription is an accepted path. Deterministic coverage now exists for cancellation on every adapter (Codex interrupt, ACP cancel, Claude Code and Antigravity process-tree kill, 2026-10-17), for terminal attachment to a suspended Claude Code or Codex session, and for resume on wake (Claude Code resumes under full autonomy; Codex starts fresh because `thread/resume` carries no `dynamicTools` in codex-cli 0.153.4 or 0.162.0-alpha.17.2); the live proofs of each remain owner-authorized.
2. Prove native policy coverage before enabling governed OpenCode tasks or Claude ask/self-decision. An approval bridge alone cannot control actions a provider auto-allows. The excluded Grok adapter remains refused for governed delivery. Checked on 2026-10-17 against the vendors' current documentation: Claude Code evaluates `allow` rules from user, project, local, and `--settings` files before it prompts, and only the managed-settings tier (`allowManagedPermissionRulesOnly`) can make the harness the sole source of permission decisions; Lazoo cannot set that tier from the CLI, so Claude ask/self-decision delivery stays refused by design rather than by omission. OpenCode loads `OPENCODE_CONFIG_CONTENT` and the inline `OPENCODE_PERMISSION` block after the global, custom, project, and `.opencode` configuration and below only macOS managed configuration, and a top-level `"*": "ask"` rule covers built-in and MCP tools alike; a per-launch forced permission block is therefore the candidate mechanism for OpenCode governed delivery, but the ACP bridge admits only execute and edit requests today, so widening the admitted tool kinds and the live `session/request_permission` proof remain owner decisions.
3. Raw-history retention is now a second archive kind (schema 19, 2026-10-17: redacted raw provider frames of completed turns within the shared quota; wire frames that map to no event are not captured). Terminal takeover exists only as suspend-then-attach for Claude Code and Codex; a live native TUI while Lazoo drives turns needs the owner to choose between takeover, fork, or a rendered transcript (section 27), and UI binding stays separate.
4. Verify the aggregate budget with the separately owned desktop and representative memory/terminal workloads; the current cap explicitly covers daemon/keeper/CLI only.
5. Extend configuration apply beyond the verified Codex MCP format only with exact version/schema evidence.
6. Investigate the intermittent CLI timeout and previously observed Windows heap-corruption exit. Neither is causally fixed. Since 2026-10-17 every `lazooctl` wait is bounded (5 s request write, 20 s read-only response, 600 s otherwise, `LZ-IPC` exit 3 naming the phase) and the governor initialization lock times out after 5 s, so a recurrence is recorded with a phase instead of killed; neither bound is a causal fix. The longer stress pass is evidence of the tested run only; governor initialization and ordinary RPC receipt currently have unbounded waits and are diagnostic candidates, not proven causes.

Connectors, vector retrieval, and voice remain outside this request.
